# S4 LAN 사용자 시연 (2026-11-05)

- 시나리오: `S4`. LAN의 다른 PC에서 계정으로 로그인해 S1~S3을 쓴다.
- 기준: `config/project-completion-criteria.json`의 S4. ADR-0017. 판정 항목은
  `docs/superpowers/specs/2026-10-11-purecvisor-desktop-node-s4-lan-account-design.md` 1절이다. 사용자 순서표는
  `docs/ga-ready/demo/s4-lan-runbook.md` 3절이다.
- 이 기록은 설치본 `0.42.96-admin-smoke`의 시연 초안이다. 승격 근거가 아니고, public trusted signing이나 external stable
  publication을 주장하지 않는다.
- 진행 상태: 시연 중. 2026-11-05 S2에서 멈췄고 2026-11-08 재개를 기다린다. 확인자 칸은 비어 있다. 판정 전이며 S4 통과를 주장하지 않는다. 리허설 R은 판정 근거가 아니다.

주소는 `<host-lan-ip>`만 쓴다. 비밀번호, token, 실제 LAN 주소, 호스트명, 사용자 홈 경로는 적지 않는다.

## 시연 전 상태

2026-11-05에 읽은 상태다. 시연은 아직 시작하지 않았다.

- 설치본: PureCVisor Desktop Node `0.42.96` (operational current `0.42.96-admin-smoke`).
- service `PureCVisorDesktopNode`: Running, StartMode Auto. 실행 파일은 설치본 `DesktopNode.Host.exe`.
- 명령줄: `--prefix "http://<host-lan-ip>:7777/" --web-prefix "http://<host-lan-ip>:80/" --allow-lan`.
  `--api-token-credential-target "PureCVisor/PureCVisorDesktopNode/api-token"`.
- `--batch-evidence-root`는 저장소 상대 경로 `artifacts/batch-runs/full-admin-host-mutation-gate-20261011-04296`를 가리킨다.
  그 폴더는 없다. 로컬 저장소를 2026-11-05에 다시 클론하면서 gitignore된 artifacts가 빠졌다.
- listener: TCP 7777과 80이 LAN 주소다 (http.sys). loopback listener는 없다.
- 방화벽 관리 규칙 2개: `PureCVisor Desktop Node Local API LAN`, `PureCVisor Desktop Node Web LAN`. Enabled, Profile
  `Private`, Inbound.
- 계정 (`accounts.json`, 해시 제외): `pcv-admin` admin enabled, `pcv-s4-operator` operator enabled.
- VM:
  - `pcv-guest-installed-04253-r1` Off, Generation 1. 디스크가 있다. 보존 VM이다.
  - `pcv-it-s2-source` Off, Generation 2. 디스크와 Ubuntu DVD가 있다. S2 template다.
  - `pcv-it-s4-*`는 없다.

## 진행 기록

- 2026-11-05: 사용자가 `pcv-admin` 비밀번호를 잊었다. 사용자 요청으로 admin `pcv-admin2`를 만들었고(비밀번호는 사용자 전용 파일로만 전달), 다른 PC 로그인을 확인한 뒤 `pcv-admin`을 disable했다.
- 2026-11-05 사용자 보고: 다른 PC 브라우저 로그인(순서 1·2)과 S1(Generation 2 VM `pcv-it-s4-console` 생성, 콘솔 입력 반영, 순서 3)을 확인했다. S2(순서 4)는 설치본 VM 상세에서 복제 이름 칸이 자원 격자 안에 묻혀 있어 멈췄다. 이 결함이 Web Console 재설계 campaign `ui-redesign-20261105`의 계기다. 확인자 칸은 사용자가 채울 때까지 비워 둔다.
- 재설계는 `main`에 merge됐지만(Task 1~10, 마지막 PR #107 `9036c62`) 설치본 반영은 S4 판정 뒤 release train이다. 그래서 이 시연은 설치본 `0.42.96` 화면으로 이어 간다. S2 복제 이름은 VM 상세 자원 격자의 `Target VM name` 칸에 넣고, 이름은 `pcv-it-s4-` 접두사로 한다(끝 상태 정리 대상).
- 2026-11-08 중간 상태(읽기만, 바꾼 것 없음):
  - service Running, StartMode Auto. 명령줄의 LAN prefix 두 개와 `--allow-lan`은 시연 전과 같다.
  - listener TCP 7777과 80이 LAN 주소다.
  - 방화벽 관리 규칙 2개는 Enabled, Profile `Private`, Inbound다.
  - 계정: `pcv-admin` admin disabled, `pcv-s4-operator` operator enabled, `pcv-admin2` admin enabled.
  - VM: `pcv-guest-installed-04253-r1` Off Generation 1(보존), `pcv-it-s2-source` Off Generation 2(S2 template), `pcv-it-s4-console` Running Generation 2(S1 시연 VM).

## 사용자 확인

사용자는 자기 PC의 브라우저만 쓴다. 로그인은 admin `pcv-admin2`다(2026-11-05 재발급). 확인자 칸은 사용자가 채운다.

| 순서 | 사용자 브라우저 | 확인할 것 | 확인자 |
| --- | --- | --- | --- |
| 1 | `http://<host-lan-ip>/`를 연다 | 로그인 페이지. loopback 세션을 쓰지 않는다 |  |
| 2 | 사전 단계의 admin 계정으로 로그인한다 | 역할이 화면에 맞다 |  |
| 3 | S1. ISO로 Generation 2 VM을 만들고 콘솔을 연다 | 화면이 비어 있지 않고, 입력 뒤 화면이 바뀐다 |  |
| 4 | S2. template을 잠그고 복제한다 | 복제 job이 한도 안에 끝난다 |  |
| 5 | S3. checkpoint를 만들고, 복원하고, 예약을 미리본 뒤 저장한다 | 예약 checkpoint가 생기고, 끝나면 예약을 지운다 |  |
| 6 | 시연 VM을 끈다 | `pcv-it-s4-*`만 대상이다 |  |

예약 저장 뒤 `next_due_at`이 지나야 예약 checkpoint가 생긴다. 사용자는 그동안 자리를 비워도 되고, 확인은 그 뒤에 한다.

## 판정

- 판정 전이다. S4 통과를 주장하지 않는다.
- 설계 1절의 세 항목(다른 PC 브라우저 로그인, 그 세션의 S1~S3, Private/`LocalSubnet`와 끝 상태)은 아직 기록되지 않았다.
- `config/project-completion-criteria.json`의 S4는 `open`이고 `demo_record`는 `null`이다. 이 초안은 그 칸을 바꾸지 않는다.
- `pcvverify completion`은 돌리지 않았다. 완료, 승격, public trusted signing, external stable publication을 주장하지 않는다.
