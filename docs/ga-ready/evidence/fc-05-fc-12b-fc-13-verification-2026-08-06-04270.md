## 3. FC-12(b) — 비 ASCII stdin/credential: 호스트 측 `PASS`, guest 측 `미확정`

> **후속 종결 (2026-08-06):** guest 측이 닫혔다. 원인은 이 절이 저울질한 두 가설 중 어느
> 쪽도 아니라 **argv 전달**이었다. bridge가 argv를 공백으로 이어붙여 guest에서 재파싱했고,
> 표본이 공백에서 쪼개져 여러 줄로 출력된 것이 아래 `27` bytes의 정체다. 인코딩은 깨진 적이
> 없다. 수정과 실제 guest 실측은
> `docs/ga-ready/evidence/guest-exec-argv-fidelity-fc-12b-closure-2026-08-06.md`가 소유하며,
> 수정 후 표본은 기대 UTF-8 길이와 정확히 같은 `31` bytes로 돌아왔다. 아래 서술은 조사 시점
> 기록으로 보존한다.

호스트 측 계약은 `dcb703ad`가 `StandardInputEncoding`/`StandardOutputEncoding`/
`StandardErrorEncoding`을 UTF-8로 고정하면서 닫혔고
`src/DesktopNode.HyperV.Tests/GuestExecutionTransportEncodingTests.cs`가 이를 잠근다. 감사 §12.2가
"`0`건"으로 기록한 상태는 감사와 같은 날 해소됐다.

guest 측 왕복은 **이 실행에서 확정하지 못했다.** 관측값은 아래와 같다.

| 시도 | guest 명령 | `stdout_byte_count` |
| --- | --- | ---: |
| A | `hostname` | `17` |
| B | `powershell -NoProfile -Command "Write-Output abc"` | `5` |
| C | `powershell -NoProfile -Command "[Console]::Out.Write('abc')"` | `0` |
| D | `powershell -NoProfile -Command "Write-Output '<비 ASCII 표본>'"` | `27` |
| E | base64로 guest에서 문자열을 만들어 `Write-Output` | `0` |

표본 `café 한글 日本語 Ж Ω ß`의 UTF-8 길이는 `31` bytes, CRLF 포함 `33` bytes이고, OEM 코드
페이지로 손실되면 `19` bytes다. 시도 D의 `27`은 **둘 다 아니다.**

다만 시도 C와 E는 순수 ASCII인데도 `0` bytes를 냈다. 즉 `0`/불일치는 비 ASCII와 상관없이
`$`, `;`, `[`, `(` 같은 문자가 든 명령에서 발생한다. 따라서 이 관측은 stream 인코딩 결함이 아니라
**guest-exec route의 argv 전달** 쪽을 가리킨다. 두 가설을 분리하지 못했으므로 어느 쪽도 결함으로
확정하지 않고, FC-12(b) guest 측은 `미확정`으로 남긴다.

후속 대상: `vm.guest.exec`가 특수문자를 포함한 argv를 guest에 어떻게 전달하는지 별도 조사.

## 5. 이 실행이 guest 자산에 남긴 변화

`pcv-guest-installed-04253-r1`은 `AutomaticCheckpointsEnabled=True`다. 기동 전 checkpoint는 `1`개
였고 종료 후 `0`개다. Hyper-V 자동 checkpoint는 기동 시 만들어지고 종료 시 병합·제거되므로, 기동
전에 남아 있던 `1`개는 2026-05-27 세션의 잔여 자동 checkpoint였고 이번 기동·종료로 병합됐다.

| 항목 | 기동 전 | 종료 후 |
| --- | --- | --- |
| state | `Off` | `Off` |
| checkpoints | `1` | `0` |
| 연결 디스크 | `pcv-guest-installed-04253-r1_4F2FD1E4-...avhd` | `pcv-guest-installed-04253-r1.vhd` |
| Notes / keep policy | 유지 | 유지 |

종료 후 연결 디스크는 `04253` evidence가 `differencing_vhd_path`로 기록한 경로 자체이고 parent는
image-cache의 Windows Server 2022 eval base VHD다. VM identity, Notes, keep policy, credential은
그대로다. 그러나 **자동 checkpoint 병합은 이 실행의 부작용이며 의도한 것이 아니다.**

권고: evidence anchor 자산에서 `AutomaticCheckpointsEnabled`를 끈다. 켜져 있으면 단순 기동만으로
디스크 체인이 조용히 바뀐다. 이 변경 자체가 keep policy 자산에 대한 추가 mutation이므로 이번
범위에서는 실행하지 않고 권고로만 남긴다.
