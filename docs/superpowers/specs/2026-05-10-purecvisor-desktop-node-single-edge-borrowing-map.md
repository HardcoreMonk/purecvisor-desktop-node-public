# PureCVisor Single Edge Backend/Frontend Borrowing Map

작성 기준: 2026-05-10

## 목적

`D:\data\projects\codex-zone\purecvisor-single`의 Linux Single Edge 전체 소스에서
백엔드 로직과 프론트엔드 로직을 기능 단위로 식별하고, Windows Desktop Node
저장소에서 차용 가능한 항목과 그대로 가져오면 안 되는 항목을 분리한다.

Windows/Hyper-V 전용 저장소이며 Linux `purecvisorsd`, KVM/libvirt, LXC, ZFS,
OVS/OVN, DPDK/SR-IOV runtime code를 제품 경로에 추가하지 않는다.

Backend control-plane shape:

- `purecvisorsd` starts from `src/main.c`, initializes libvirt, dispatcher, UDS,
  REST, optional gRPC, telemetry, audit, jobs, and systemd notification in one
  Linux daemon process.
- REST is a facade over internal UDS JSON-RPC. Many `/api/v1/...` routes are
  translated into RPC method names before dispatcher execution.
- Dispatcher owns method policy, fire-and-forget async contracts, owner-scope
  checks, and route registration.
- Auth/account state is SQLite-backed (`rbac.db`) with JWT access tokens,
  refresh-token sessions, API keys, roles, and optional tenant metadata.
- Async work uses SQLite job persistence plus audit and WebSocket completion
  events.

## 차용 준비 Batch

### Batch A: 문서/계약 고정

- 이 문서를 Single Edge borrowing source map으로 유지한다.
- `web/DESIGN.md`는 visual/UI clone contract owner로 유지한다.
- Windows route set은 `web/src/served/routes.ts`와 `DesktopNodeApiRequestProcessor` 기준으로 고정한다.
- Linux runtime/import 금지 문자열 guard는 active Web Console test에 계속 둔다.

### Batch B: Frontend-only reusable UX

- table/filter/sort/empty/error/loading state를 VM/jobs/network/evidence에 통일한다.
- command palette와 global search를 Windows view/action set으로만 추가한다.
- job progress/detail/failure drilldown을 Linux event-center 패턴으로 재해석한다.
- token/session status copy는 browser token boundary만 표현한다.

### Batch C: Windows-native backend parity 후보

- VM detail의 hardware/storage/network field를 Hyper-V adapter가 제공하는 범위에서 확장한다.
- guest shutdown/status처럼 Windows evidence가 있는 route만 UI에 노출한다.
- Event Log/provider, diagnostics, evidence ledger를 event-center style로 묶는다.
- WebSocket live events, backup/template, Linux noVNC backend은 별도 ADR 없이는 시작하지 않는다.

### Batch D: Optional assets/package slice

- Pretendard/Coolicons를 가져올 경우 license, payload size, host content-type, MSI payload, parity manifest를 함께 갱신한다.
- service worker/manifest/offline은 installed listener/static cache evidence 없이는 보류한다.

## 권장 다음 구현 순서

1. Optional vendor asset slice는 license/payload/content-type evidence gate로 분리.
2. VM detail tabs의 hardware/storage/network field는 Hyper-V adapter field가 확정된 항목만 확장.
3. Event Log/provider installed evidence가 안정화되면 event-center source로 추가.
4. WebSocket live events, Linux noVNC backend, backup/template은 별도 ADR 전까지 보류.
5. noVNC vendor asset slice는 license, payload, and content-type evidence gate로 분리.

## 결론

Linux Single Edge에서 바로 가져올 수 있는 것은 시각 체계, shell density, route
registry discipline, API/error helper pattern, table/job/event UX, validation guard
culture다.

그대로 가져오면 안 되는 것은 backend runtime, Linux host mutation logic, account/RBAC
Linux JWT stack, WebSocket/noVNC backend, container/storage/OVN/DPDK/SR-IOV 화면이다. Windows
Desktop Node는 Hyper-V native adapter와 single bearer token boundary를 유지하면서
UX와 frontend 구조만 선별 차용해야 한다.
