# Security Policy

## Reporting a vulnerability

Use GitHub private vulnerability reporting from this repository's **Security** tab. Include the affected
component, reproducible conditions, impact, and the smallest safe proof needed to validate the report.

Do not publish suspected vulnerabilities, credentials, host identifiers, private endpoints, or exploit
details in a public issue or discussion. If private vulnerability reporting is temporarily unavailable,
wait for that channel to be restored rather than disclosing sensitive material publicly.

## Scope and response boundary

- Reports about the current source tree and its documented Windows Desktop Node boundary are in scope.
- Historical evidence is informational and may describe versions that are no longer current.
- Public source visibility is not a bug-bounty offer, service-level commitment, or permission to test systems
  that you do not own or lack authorization to assess.
- Do not perform denial-of-service, social-engineering, credential-harvesting, persistence, or destructive
  testing.

The repository does not publish a trusted stable binary release. The current claims remain
`public_trusted_signing=false` and `external_stable_publication=false`.
